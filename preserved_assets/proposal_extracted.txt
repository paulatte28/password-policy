Project Objectives:
To develop a web-based system that evaluates password policy settings and reports compliance for length, complexity, lockout, and expiration.
To identify weak-password risks, password reuse policy gaps, and insecure configurations, and provide recommendations with a compliance score.
To implement role-based access control, audit logging, and report exports while never requesting or storing the actual passwords of users.
Project Description:
PasswordPolicy Checker is a web-based system that checks password policy rules. It is made for system administrators, IT security officers, auditors, and school IT departments. Users enter or import policy settings such as minimum length, complexity rules, lockout, expiration, and password history. The system compares these settings with security standards like NIST SP 800-63B and OWASP, then shows a clear report. Users expect the system to be easy to use, fast, and accurate. The system checks the rules only. It never asks for or stores real user passwords.

Weak password policies are a common cause of security problems. A short minimum length, no lockout, or no limit on reusing old passwords makes it easier for attackers to guess or brute-force passwords. This system helps organizations find these gaps early and fix them. It saves time compared to checking policies by hand, and it keeps records that can be used for audits. It can also help students learn what a good password policy looks like.

The system will be built with C# and .NET using ASP.NET Core MVC. Entity Framework Core and SQL Server will store policies, results, and audit logs. ASP.NET Core Identity will handle login and user roles. It stores only hashed passwords for the system's own staff accounts, not the passwords being audited. Razor Views with HTML5, CSS3, and JavaScript will be used for the screens, Chart.js for the charts.

These technologies were chosen because they are secure, well documented, and work well together. ASP.NET Core MVC keeps the checking rules separate from the screens, so the rules are easy to check and update. SQL Server is reliable for saving history and audit records. Razor Views let us build pages with C# and HTML together, and HTML5, CSS3, and JavaScript are standard web tools that are easy to use. Git/GitHub makes teamwork easier.

The standards are not fixed in the code. Administrators can edit the limits, because security guidelines change over time. The system does not connect to live systems and does not test real passwords. It only evaluates the policy settings that users provide, which keeps it safe and focused on the project goal.
